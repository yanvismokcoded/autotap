# tap-bot

Урезанная версия vz-бота — оставлена **только функция тапа**.

## Что есть
- Многопользовательский логин (каждый входит в свой Telegram-аккаунт)
- `/genkey`, `/activate` — регистрация по ключу от владельца
- `/login`, `/code`, `/password`, `/logout`, `/resend_code`, `/login_code`, `/api` — вход в аккаунт
- `/login_qr` — вход по QR-коду (сканировать с другого устройства: Настройки → Устройства → Подключить устройство), `/cancel` — отмена; при 2FA после скана вводится `/password`
- Автопересылка кодов входа из служебного чата Telegram (777000) в личку
- `/add_channel`, `/channels`, `/del_channel`, `/create_channel` — список каналов, которыми тапаем
- `/tap <ссылка> @юз [количество]` — сам тап (можно и без юза — возьмёт из поста/пересланного сообщения)
- **Несколько голосований сразу:** `/tap ссылка*юз ссылка*юз2` — или просто пришлите боту такое сообщение без команды (например, пересланное «ищем вз ссылка*юз ссылка*юз2»). Пар может быть сколько угодно; чёрный список юзов учитывается
- **Пост → юз → ответ:** перешлите боту пост с голосованием, затем юз (`@юз`, `юз: имя` или просто имя) и **ответьте на сообщение с юзом** (любым текстом). Бот берёт только *прошлый* пост, смотрит под ним последние 300 комментариев и тапает, только если там уже есть голоса за этот юз. Если нет — не тапает и предлагает кнопку «Всё равно тапнуть». 👀 под сообщением = бот запомнил пост/юз
- **Прогресс в реальном времени:** бот присылает одно сообщение и правит его по ходу — «тапнуто: 3/10» (по блоку на каждое голосование). Тап идёт в фоне, бот при этом отвечает на другие команды; задачи одного пользователя идут по очереди. `/cancel` — остановить после текущего канала
- `/beta [on|off]` (только владелец) — новые функции тапа (пачки `ссылка*юз`, «пост → юз → ответ», живой прогресс, `/cancel` для тапа) по умолчанию доступны **только владельцу**; `/beta on` открывает их всем, `/beta off` закрывает обратно. Остальным до этого `/tap` работает по-старому. Флаг хранится в конфиге (`betaOpen`)
- `/del_tap` — забыть тап по посту
- `/settings`, `/set votes <число>`, `/status`

## Чего нет (в отличие от исходного vz-бота)
Убрано всё, что не относится к тапу напрямую:
- слежение за вз-чатами и автоматический поиск/предложение вз (`offers.js`)
- согласование "сообщите"/"тап после вас" и договоры о вз (канал договоров)
- автопост/рассылка по чатам, папки чатов
- техподдержка (`/support`)

Если что-то из этого понадобится обратно — вернуть несложно, файлы `userbot.js`, `tapper.js`, `parser.js` не менялись и совместимы с исходным проектом.

## Хранение данных

Нужен Node.js 18+ (используется глобальный `fetch`).

Бот хранит `config.json` и `users.json` (там же лежат сессии всех аккаунтов)
либо на диске, либо в Upstash Redis — выбирается автоматически:

- **Есть диск** (свой сервер, Railway с volume и т.п.): просто задай
  `CONFIG_DIR` (или ничего не задавай — по умолчанию `/app/data`).
- **Нет диска** (Render Free и подобные): заведи бесплатную базу на
  [upstash.com](https://upstash.com) (Redis, Free tier), скопируй со страницы
  базы **REST URL** и **REST TOKEN**, и задай их как переменные окружения:
  `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`. Как только они заданы —
  файл на диске вообще не используется, всё живёт в Upstash и переживает
  рестарты/редеплои.

## Запуск

Переменные окружения (или `config.json` на основе `config.example.json`):
`API_ID`, `API_HASH`, `BOT_TOKEN`, `OWNER_ID` (необязательно),
и при работе без диска — `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`.

```
npm install
npm start
```

Первый, кто напишет боту `/start`, становится владельцем.
